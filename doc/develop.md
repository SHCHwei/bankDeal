# 專案開發需求：銀行模擬交易系統 (Bank Transaction Simulator)

## 1. 專案主旨

本專案旨在開發一個模擬銀行系統接收並執行金錢進出（存、扣款）的請求流程。

---

## 2. 環境配置 (Infrastructure)

使用 Docker 容器建立一致的開發與運行環境：

* Golang 環境：建立並配置 Go 容器。
* 資料庫環境：建立關聯式資料庫（如 PostgreSQL 或 MySQL）容器。
* 容器編排：使用 docker-compose 同時啟動應用程式與資料庫。

---

## 3. 資料建模與初始化 (Data Modeling)

設計資料庫 Schema 並撰寫初始化腳本（或使用 Migration 工具）建立以下實體：
### 3.1 核心實體

 | 實體名稱                                 | 說明                      |
 |--------------------------------------|-------------------------|
 | 銀行 (Banks)                            | 紀錄銀行代碼、名稱與總行資訊。         |

 | 戶頭 (Accounts) | 紀錄帳戶餘額、所屬人類、銀行關聯以及帳號狀態。 |

### 3.2 假資料建立
實作資料初始化（Seeding）功能，自動產生預設的銀行、客戶與對應的虛擬戶頭。

---

## 4. 核心功能：交易模擬 (Core Logic)

實作背景執行任務，自動觸發金錢變動邏輯：
* 隨機存款 (Random Deposit) ：
  * 每隔一小時觸發一次。
  * 隨機挑選人類/戶頭執行存款操作。
* 定期扣款 (Periodic Deduction)：
  * 針對特定標記的客戶，設定固定頻率（如特定時間點）執行自動扣款（如服務費、保險等）。
* 請求處理：
  * 模擬接收外部請求後，精確執行餘額計算與狀態更新。

---

## 5. 測試與品質控管 (Testing)

* 單元測試 (Unit Testing)：
    * 針對存款與扣款邏輯撰寫測試。
    * 確保餘額計算正確，避免發生負數餘額或並行存取（Concurrency）造成的數據錯誤。
